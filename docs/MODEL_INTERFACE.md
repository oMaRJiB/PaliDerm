# Local model inference interface

The application imports only these two functions. All model and preprocessing
decisions stay in `backend/ai/model_interface.py` and its adapters.

```python
from backend.ai.model_interface import load_model, predict_case

# Once at process startup, using an administrator-provided local model.
load_model("models/best_model.pth")

case_result = predict_case(
    images=["patient/image1.jpg", "patient/image2.jpg"],
    symptoms={"itching": True, "pain": False, "duration_days": 14},
    metadata={"age": 35, "location": "arm"},
)
print(case_result)
```

This example assumes the supplied model's saved feature contract describes those
inputs. The app never constructs tensors. Images can be a single item or a list
of local paths, PIL images or encoded image bytes. In the encrypted application,
authorize the case, then pass `ImageStorage.read_original(...)` bytes; never point
the predictor at encrypted files or create plaintext temporary files. This layer
does not authorize HTTP requests or read application databases.

`load_model` installs a model only after loading and contract checks succeed. A
failed replacement preserves the previous model. Each prediction uses one
consistent model instance; inference is serialized per instance. Use one model
per process, or retain the returned `LoadedModel` for independent instances.

## Supported artifacts

- **Existing SCIN MobileNet:** pass its `best_model.pt` or exported `app_model`
  directory. The saved architecture, image statistics, class order and adjacent
  `metadata_encoder.json` are loaded automatically. Bundle hashes and the
  checkpoint's encoder hash are checked. Reconstruction never downloads weights.
- **HW3 custom CNN + metadata:** pass `SCIN_custom_model.keras`, alongside
  `SCIN_custom_metadata_encoder.json` and `SCIN_custom_classes.json` generated by
  the notebook. Input resolution comes from the saved model; RGB `/255` and the
  notebook's exact Pillow letterbox centering are retained. Renamed models can
  identify artifacts explicitly using the sidecar below. TensorFlow is optional
  and imported only for `.keras` models. No `.h5`, arbitrary custom object or
  unsafe Lambda deserialization fallback is enabled.
- **TorchScript:** detected by archive contents, independent of `.pt`/`.pth`
  extension. Configuration may be embedded with
  `torch.jit.save(model, path, _extra_files={"inference.json": json.dumps(config)})`
  or supplied as JSON alongside the model.
- **PyTorch checkpoint dictionaries:** `model_state_dict`, `state_dict`, and
  tensor-only `model` dictionaries are accepted. Raw tensor state dictionaries
  are also supported with a registered architecture and saved dimensions/config.
  A uniform DataParallel `module.` prefix is removed before strict loading.

PyTorch uses CUDA when available, otherwise CPU, and always `eval()` plus
`inference_mode()`. Keras calls use `training=False` on CUDA when available,
otherwise CPU. Apple MPS/Metal is not automatically selected by this interface.

Only load trusted local model artifacts: TorchScript itself contains executable
model operations. PyTorch pickle loading uses
[`weights_only=True`](https://docs.pytorch.org/docs/stable/notes/serialization.html) and never
retries with `False`. Optional **preprocessing** pickle files require the explicit
administrator call `load_model(path, trust_pickle=True)`; this can execute code.
JSON is the default. Pickles must expose saved input feature names or declare
`metadata.feature_names`. Compressed joblib files are not supported.

## Inference configuration

Use `<model filename>.json` (for example `best_model.pth.json`) or
`inference_config.json` in the model directory. File-specific JSON takes priority.
Saved checkpoint configuration is read first; a sidecar can add aliases/defaults,
but cannot contradict its architecture, dimensions, class order or saved image
size/normalization. Keep a separate directory for each model's artifacts.

```json
{
  "architecture": "mobilenet_v3_small_metadata_late_fusion",
  "model_kwargs": {"metadata_dim": 68, "num_classes": 41},
  "model_version": "experiment-1",
  "target_classes": ["replace with every class in exact training order"],
  "inputs": "image_metadata",
  "image": {
    "size": 224,
    "resize": "pad",
    "scale": 255,
    "mean": [0.485, 0.456, 0.406],
    "std": [0.229, 0.224, 0.225]
  },
  "metadata": {"encoder": "metadata_encoder.json"},
  "output": {"type": "softmax_logits"},
  "multi_image": "mean_probabilities"
}
```

The class placeholder must be replaced; the loader checks actual output width.
For generic models, metadata can instead use ordered descriptors:

```json
{
  "features": [
    {"name": "age", "kind": "numeric", "mean": 40, "std": 15, "default": 40},
    {"name": "itching", "kind": "binary"},
    {"name": "sex", "kind": "categorical", "categories": ["female", "male", "unknown"]}
  ],
  "aliases": {"itching": "itching"}
}
```

This object belongs under `metadata`, or in an encoder JSON file. Feature/category
order comes from saved artifacts, never sorted request keys. Numeric values use
`(value - mean) / std`. Unknown categorical values produce zero blocks and a
warning. Missing generic numeric/binary fields use configured defaults, otherwise
zero with a warning. Conflicting symptoms/metadata fields and nonfinite values
are rejected. SCIN's saved binary columns are stricter: missing/unknown answers
raise an error unless a model-specific default is explicitly configured. Unknown
must not silently become an absent symptom. Encoder paths stay inside the bundle.

The existing SCIN models require more features than the application collects.
`age`, `sex`, `location` and six symptoms alone cannot recreate those features.
Provide actual SCIN fields or an explicit, training-compatible mapping/default
policy through saved aliases/descriptors. This layer does not guess age/duration
bins, skin type or unreported symptoms. Free-text symptoms are accepted as context
but not embedded by these adapters; returned warnings disclose this limitation.

## Multiple images and output semantics

`multi_image` defaults to `mean_probabilities`: preprocess every image, broadcast
the case metadata, activate per-image outputs, then average probabilities.
`mean_embeddings` is available for the existing MobileNet adapter and averages
projected image features before metadata fusion. `stack` passes `[N,3,H,W]` to a
TorchScript/model-specific adapter which must return one case output. These
aggregation strategies are inference choices, not evidence of training or
validation on multiple images. The generic Keras adapter supports probability
averaging; other fusion strategies require a matching adapter.

`image.size` accepts an integer or `[height,width]`; `scale` is a divisor.
`resize` accepts manual `pad`, `stretch`, or `pillow_pad`. The two padding modes
are distinct to reproduce the two existing models' training transforms exactly.

`output.type` supports:

- `softmax_logits`: stable softmax, including models trained on soft labels.
- `sigmoid_logits`: independent sigmoid probabilities; their sum need not be one.
- `probabilities`: already activated scores in `[0,1]`, preserved without a second
  softmax or sigmoid, including weighted multi-label probabilities.
- `weighted_scores`: nonnegative positive-sum scores normalized per row.
- `auto`: use known final activation when available; otherwise recognize bounded
  outputs as probabilities or apply a disclosed softmax logit fallback.
  `output.multi_label=true` selects sigmoid for that logit fallback.

Arbitrary logits do **not** reveal sigmoid versus softmax training. Even bounded
values can be logits, so declare semantics when exporting. The interface reports
auto-mode ambiguity rather than claiming it can infer the training objective.
Dictionary/tuple outputs can select `output.key`/`output.index`. Invalid dimensions,
NaNs, infinities and out-of-range declared probabilities fail explicitly.

Results contain `top_prediction`, all ranked `differential` entries,
`triage_flags`, `model_version`, `output_format`, `warnings` and
`probability_notice`. Missing class mappings use visible `class_N` placeholders;
missing image settings use visible 224px/ImageNet defaults. No configured model
raises `ModelNotLoadedError`; bad files/contracts raise `ModelLoadError`; invalid
case inputs/outputs raise `PredictionError`. Scores are uncalibrated and are not
clinician-confirmed diagnoses.

## Future models and separate triage

Future TorchScript image/image+metadata models need only saved configuration.
Future raw state-dict architectures implement `TorchAdapter.build_model(config)`
in a model-specific subclass and call `register_adapter(name, AdapterClass)` during
model setup. No arbitrary import strings or `eval` are read from model JSON. The
application still calls the same two functions; no UI/training changes are needed.

`backend/ai/triage.py` interprets only the user's supplied prototype examples:
top-ranked melanoma/SCC class, explicitly reported spreading/rapid spreading,
fever **and** skin-infection signs, and immunocompromised status. It adds review
flags without modifying neural predictions. There are no invented probability
thresholds, NLP symptom detection, emergency classifications, prescriptions or
automatic red/amber/green priority. An empty flag list is not reassurance.

The Flask typed `AnalysisInput`/`AnalysisOutput` adapter remains unchanged and
unconfigured by default. This task adds an inference API and usage example; it
does not enable automatic analysis on submission, change consent/permissions,
populate missing clinical inputs, or alter AI attempt persistence. A configured
application adapter can call these functions after authorization and map ranked
results to `Candidate`, retaining `triage_level='undetermined'` until an approved
priority policy exists. Clinical review remains independent of inference.

The notebook's existing Keras export did not record a model-to-encoder hash.
This loader rejects a conflicting companion or sidecar replacement and checks
dimensions, but cannot recover historical provenance if the original companion
was overwritten. A trusted bundle manifest can bind the files supplied together.


Use the existing ML environment from `requirements-ml.txt`. Keras checks require
an already installed compatible TensorFlow/Keras runtime; Flask-only environments
can import the interface without importing either model framework. No model
training or downloads are performed by loading or by the synthetic tests.

Actual checks on 2026-10-11: **78 tests passed** (65 existing + 13 interface
tests). A separate CPU smoke check loaded the existing trained MobileNet bundle
and matched all 41 scores to its original predictor within numerical tolerance.
The custom CNN check builds the existing notebook graph, saves/reloads a temporary
`.keras` export and tests inference; it does not train the model. Tests also cover
TorchScript, restricted state dictionaries, multiple-image modes, exact padding,
encoding, class/encoder mismatch, unsafe pickle rejection, nonfinite output,
overflow-safe weighted scores, sanitized errors and the supplied triage examples.

Tested environment: torch 2.14.1, torchvision 0.29.1, TensorFlow 2.22.0rc0,
Keras 3.15.1, NumPy 2.5.4 and Pillow 12.3.0. These are the already-installed
versions; this task installed nothing. CUDA execution was not exercised on this
CPU-only test path. Framework deprecation warnings remain. No training code,
notebook cells, application routes, schema or existing AI adapter were changed.
